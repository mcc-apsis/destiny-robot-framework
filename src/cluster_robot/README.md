# Cluster Robot

The [**`ClusterRobot`**](https://github.com/mcc-apsis/destiny-robot-framework) extends the robot framework to support computationally intensive enhancement generation on high-performance computing (HPC) clusters. The workflow of a robot is separated into three stages.

In the **preparation stage**, the robot downloads enhancement batches from the DESTINY repository, prepares the input files required for processing, and submits a Slurm job to the compute cluster. The actual enhancement generation is performed entirely by the cluster job.

In the **wait stage**, the robot waits for the submitted Slurm jobs to finish. It continuously queries the Slurm API to check the status of the submitted jobs and proceeds to the upload stage once they have completed successfully.

In the **upload stage**, the robot collects the output produced by the cluster jobs, converts it into DESTINY enhancements, and uploads the results back to the DESTINY repository.

The `ClusterRobot` consists of the following components:

* **`robot.py`** implements the three main workflows:

  * `prepare_all()`, which downloads enhancement batches, prepares the input data, and submits the cluster jobs.

  * `wait_all()`, which waits for all submitted Slurm jobs to finish. It continuously polls the Slurm API for the status of each submitted job and proceeds once the jobs have completed successfully.

  * `upload_all_finished()`, which processes completed cluster jobs and uploads the generated enhancements.

  Similar to the `BaseRobot`, the robot-specific functionality is left abstract. New robots must implement two methods:

  * `write_input()`, which converts downloaded references into the input format required by the cluster job.

  * `parse_output()`, which reads the output generated by the cluster job and converts it into DESTINY enhancements.

* **`main.py`** provides the command-line entry point for the robot. It exposes three commands, `prepare`, `wait`, and `upload`, which execute the corresponding stages. Together, these commands provide functionality similar to the `BatchRunner` of the `BaseRobot`.

* **`batch.py`** manages the communication between the preparation and upload stages. For every downloaded enhancement batch, it creates a dedicated working directory named after the batch UID. The directory contains:

  * the generated input files in an `input` folder,
  * the output produced by the cluster job in an `output` folder,
  * Slurm log files in a `logs` folder,
  * a `metadata.json` file containing information about the batch and its processing status, and
  * an `uploaded` file once the batch has been successfully uploaded.

* **`slurm.py`** provides a wrapper for submitting and monitoring Slurm jobs. If Slurm is not available, it automatically executes the Slurm script locally, simplifying development and testing.

* **`config.py`** defines the robot configuration. In addition to the common settings, it specifies the workspace used to store batch directories (by default, the `workspace` directory inside the robot project). It also defines the **batch lease**, which specifies how long the repository reserves a claimed enhancement batch before it must be renewed. The default lease duration is **1 day and 12 hours**.

* **`client.py`** creates and configures the client used to communicate with the DESTINY repository, including authentication and HTTP settings.

* **`version.py`** provides utilities for reading and exposing the robot version from the project metadata.

## Implementation

To implement a new cluster robot, only a small number of robot-specific files are required:

* **`robot.py`**, implementing the `write_input()` and `parse_output()` methods.
* **`slurm.sh`**, together with any additional scripts required to execute the enhancement generation on the compute cluster.
* **`main.py`**, providing the command-line entry point.

A minimal custom cluster robot only needs to implement `write_input()` and `parse_output()`, as well as the Slurm script and any additional scripts required by it.

A small example implementation can be found in the [`dummy_cluster_robot`](https://github.com/mcc-apsis/destiny-robot-framework/tree/main/examples/dummy_cluster_robot).

## Configuration

The following environment variables configure the cluster robot:

| Variable                 | Explanation                                                                                                                                         |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DESTINY_REPOSITORY_URL` | URL of the DESTINY repository API the robot connects to.                                                                                            |
| `ROBOT_ID`               | Unique identifier of the robot registered with DESTINY.                                                                                             |
| `ROBOT_SECRET`           | Secret used to authenticate the robot with the DESTINY repository.                                                                                  |
| `ENV`                    | Environment in which the robot runs, e.g. `local`, `staging`, or `production`.                                                                      |
| `BATCH_SIZE`             | Number of references processed in a single batch.                                                                                                   |
| `BATCH_LEASE`            | Duration for which enhancement batches are leased from DESTINY, specified in ISO 8601 duration format (e.g. `PT6H` or `P1D`). Defaults to 1.5 days. |
| `WORKSPACE`              | Directory used to store batches and intermediate files. Defaults to `./workspace`.                                                                  |
| `SLURM_API_URL`          | URL of the Slurm API used to submit and monitor cluster jobs.                                                                                       |
| `SLURM_USER`             | Username used to authenticate with the Slurm API.                                                                                                   |
| `SLURM_TOKEN`            | Authentication token used to access the Slurm API.                                                                                                  |
| `WAIT_POLL_INTERVAL`     | Interval in seconds between Slurm job status checks. Defaults to `30` seconds.                                                                      |

## Run an example

The [`dummy_cluster_robot`](https://github.com/mcc-apsis/destiny-robot-framework/tree/main/examples/dummy_cluster_robot) executes a dummy [Slurm script](https://github.com/mcc-apsis/destiny-robot-framework/blob/main/examples/dummy_cluster_robot/slurm.sh).

Assuming that a [local DESTINY repository](https://github.com/mcc-apsis/destiny-robot-framework/wiki/7-Run-a-local-Destiny-Repo) is running, the robot folder contains a `.env` file provided by the template, and [enhancement batches](https://github.com/mcc-apsis/destiny-robot-framework/wiki/7-Run-a-local-Destiny-Repo#create-and-receive-batches) are available, the three stages can be executed from the `dummy_cluster_robot` folder with:

```bash
uv run python -m dummy_cluster_robot prepare
uv run python -m dummy_cluster_robot wait
uv run python -m dummy_cluster_robot upload
```

The `prepare` command downloads enhancement batches and submits the corresponding cluster jobs. The `wait` command waits for the jobs to complete. Once the jobs have completed successfully, the `upload` command parses the generated output and uploads the resulting enhancements to the DESTINY repository.
